# v0.4.0-alpha.2 — 2026-08-17

## Highlights

- **DocSync now supports cookie-based request authentication.** Browser apps can authenticate WebSocket connections from the handshake request, which works better with existing HttpOnly session cookies and avoids exposing session secrets to client JavaScript. (#49, #50) See the [DocSync auth docs](https://docukit.dev/docsync/auth).
- **DocSync sync is more reliable around local snapshots and pending operations.** The client and server now exchange explicit operation and snapshot payloads, which improves reconciliation when local data and server data disagree. (#51, #53)

## Breaking changes

- **Client auth config now has explicit modes.** `ClientConfig["server"]["auth"]` is now either `{ mode: "request" }` or `{ mode: "token", getToken }`. **Migration:** change `auth: { getToken }` to `auth: { mode: "token", getToken }`, or use `auth: { mode: "request" }` when authenticating from cookies on the server. (#49, #50)
- **DocSync local identity now comes from the server-verified user.** `local.getIdentity` was removed, and `Identity` no longer has `secret`. **Migration:** remove `local.getIdentity`; keep `local.provider(identity)`, and use only `identity.userId` inside the provider. (#49, #50)
- **Server authentication receives the handshake request and an optional token.** `authenticate` now receives `{ request, token? }`, and `token` can be absent in request-auth mode. **Migration:** update `authenticate` callbacks to read cookies from `request` or check that `token` exists before validating token auth. (#49, #50)
- **Server event payloads now use `clientId` instead of `socketId`.** Connect, disconnect, and sync request events report the stable DocSync client ID. **Migration:** rename event reads from `event.socketId` to `event.clientId`. (#49, #51)

## Features

- Added request-auth mode for DocSync clients and servers, including support for authenticating from WebSocket handshake requests. (#49, #50)
- Added `DocSyncServer.onDocSubscribe` and `DocSyncServer.onDocUnsubscribe` for observing document-level subscription lifecycle events. (#48)
- Allowed `useDoc({ createIfMissing })` to receive a dynamic boolean. (#54)

## Fixes

- Fixed IndexedDB persistence debounce so local operations are saved promptly while network sync can still use the collaboration-aware debounce window. (#55)
- Fixed snapshot reconciliation during sync so clients can recover when the server has a newer serialized document than the local cache. (#53)
- Removed the old client-side local identity secret from DocSync auth. (#50)

## Docs

- Rewrote the DocSync auth guide with request-auth and token-auth examples. (#49, #50)
- Updated the docs collaboration server example to use the new auth callback and subscription lifecycle events. (#48, #49)

## Internal

- Added experimental `docsync2` and `docsync2-react` packages and tests; these packages remain private and are not part of this release. (#52, afac237)
- Made DocSync sync payloads explicit across client, server, and tests. (#51)
- Hardened release automation for trusted npm publishing and deploys. (#42, #43, #44, #46, #47)

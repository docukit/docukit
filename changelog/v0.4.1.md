# v0.4.1 — 2026-09-01

## Highlights

- **Undo and redo history now survives DocSync document replacement.** When synchronization rebuilds a DocNode document from a newer server snapshot or concurrent operations, users can continue undoing and redoing their local edits instead of losing their editor history. (#59) See the [Undo Manager docs](https://docukit.dev/docnode/undo-manager).

## Features

- Added `doc.undoManager.exportHistory()` and `importHistory()` for transferring undo and redo state between matching DocNode documents. (#59)

## Fixes

- Preserved DocNode undo and redo history, including editor metadata, when DocSync replaces an in-memory document during reconciliation. (#59)
- Kept pending local edits in the replacement document when exporting history forces a commit during synchronization. (#59)
- Prevented unchanged Lexical normalization updates from overwriting newer server content during stale-while-revalidate. (#59)
- Reset DocSync push state after reconciliation errors so later synchronization attempts are not blocked. (#59)

## Docs

- Documented how to export and restore DocNode undo history. (#59)

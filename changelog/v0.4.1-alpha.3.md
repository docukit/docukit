# v0.4.1-alpha.3 — 2026-09-20

## Highlights

- **DocSync now supports the same client in pages and workers.** Shared IndexedDB identity and safer cross-tab synchronization make concurrent clients more reliable, while document closing flushes pending local work when possible. (#72, #74, #76)
- **Undo and sync reconciliation are more resilient.** Already-applied operations are treated as no-ops, stale sync attempts cannot overwrite newer state, and pending batches are acknowledged by ID. (#66, #81)

## Breaking changes

- **The client provider operation queue contract changed.** `getOperations()` now returns batches with stable numeric `id` values, and `deleteOperations()` now accepts an `ids` array instead of a positional `count`. **Migration:** update custom client providers and transaction callbacks to return `{ id, operations }` batches and delete acknowledged batches by their IDs. (#74)
- **Local identity storage changed from `localStorage` to IndexedDB.** **Migration:** do not read or write the old `docsync:localUserId` or `docsync:deviceId` keys; use the client identity APIs and await `clearLocalIdentity()` when logging out. Existing local data is reused through the versioned DocSync IndexedDB store after authentication. (#72)
- **Operations received from another tab or worker no longer enter the local undo history.** **Migration:** applications that need shared undo behavior must provide their own cross-client history; normal local edits continue to use the originating client's undo manager. (#72, #81)

## Features

- Added worker-compatible DocSync client startup without requiring animation frames or a separate HTTP endpoint. (#72)
- Added local document clock listing for providers that can read clocks without loading document contents. (#81)
- Documented concurrent clients, worker usage, and document-closing behavior in the DocSync README. (#72, #74, #76)

## Fixes

- Prevented concurrent clients from acknowledging or deleting the wrong pending operation batches. (#74)
- Preserved pending local operations across document closing and failed local writes. (#73, #76)
- Prevented duplicate inserts and unchanged state patches from creating redundant changes, including during undo and redo. (#66)
- Prevented stale connections and sync responses from changing a newer document instance or sync attempt. (#81)

## Internal

- Improved sync queue state handling, IndexedDB schema versioning, and cross-client broadcast handling. (#67, #72, #81)
